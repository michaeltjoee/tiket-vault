## Repos

### TIX-PASSPORT
- [[passport-overview]] — tiket.com's React component library ("Passport" design system), published as ~130 `@tiket/passport-*` packages to the GitHub npm registry.
- [[passport-architecture]] — One pnpm workspace package per component. Packages ship untranspiled-CSS ES modules built by plain `tsc`, and an umbrella package re-exports most of them.
- [[passport-workflows]] — PR to `main` with a changeset. Optionally label the PR for an alpha snapshot, and changesets publishes on merge through a "Version Packages" PR.
- [[passport-packages]] — All 130 workspace packages on `origin/main`. Every one is versioned in lockstep (12.8.1 at `verified_at`, see [[changesets-fixed-versioning]]).
- [[passport-accordion]] — Compound components for expandable sections. Each item owns its own open state.
- [[passport-action-banner]] — Card-style banner with image, title, description and either one or two buttons or a slide-to-confirm slider.
- [[passport-assets]] — Registry of tiket's cloud-hosted design images as named URL constants, plus Lightroom image-loader helpers.
- [[passport-badge]] — Notification dot or count pill, either overlaid on a child element or inline.
- [[passport-banner-carousel]] — Auto-scrolling promo banner carousel used by page-module. It picks a card size from visible-items count and image ratio.
- [[passport-banner-grid]] — CSS-grid layout of promo banner cards with separate mobile and desktop rows and columns, used by page-module and global-popup.
- [[passport-bottom-app-bar]] — Mobile bottom action bar container with an optional upper strip (labels, info) and a main CTA row.
- [[passport-bottom-sheet-multi-account]] — Login-nudge bottom sheet that fetches and lists blibli tiket member benefits, with "Log in now" and "Continue as guest" CTAs.
- [[passport-bottom-sheet]] — The mobile overlay primitive: portal-mounted, focus-trapped, scroll-locked, swipe-to-close, with a collapsing sticky header and an optional sticky footer.
- [[passport-bottom-tab-navigation]] — Fixed mobile bottom nav bar (Home, My Orders, Rewards, Account…) rendered from a BE-provided `navigations` array.
- [[passport-breadcrumb]] — Horizontally scrollable breadcrumb trail with overflow arrows and a pluggable link renderer, for example for `next/link`.
- [[passport-bubble-chat]] — Presentational chat message bubble with left or right alignment and an optional attachment.
- [[passport-button-slider]] — "Swipe to confirm" control. The user drags a knob to the end of the track to trigger an action, such as claiming a voucher.
- [[passport-button]] — The design-system button, rendered as `<button>` or `<a>`. It has variants, sizes, modes, a loading state, icons and a ripple on mouse-down.
- [[passport-calendar]] — Single-date and range calendar plus a month picker, with holidays, daily price tiers (cheap/best), sold-out days, and mobile, desktop and responsive renderings.
- [[passport-card-compound]] — Add-on / upsell selection card, such as an extra flight product or insurance. It has a title, ribbon, benefit list, price and an Add/Cancel button.
- [[passport-card]] — Surface container (`Card` + header/body/footer) and `CardWithNudge`, a card with a coloured top or bottom "nudge" strip that can rotate between messages.
- [[passport-chat-box]] — Pill-shaped auto-growing text input with a send/search button, for chat or AI-prompt style entry.
- [[passport-check]] — Checkbox: a native `<input type="checkbox">` inside a `<label>`, with custom tick and indeterminate visuals.
- [[passport-chips-carousel]] — Horizontal scroller for a row of chips, with prev/next arrow buttons that appear only when content overflows.
- [[passport-chips]] — `Chip` button for filters and selections, with active, error, inverted and disabled states, prefix and suffix icons, and a badge slot. Also exports `ChipsIconPulse`.
- [[passport-coachmark]] — Multi-step onboarding tour. It dims the page, spotlights a target element found by CSS selector, and shows a step pane with Skip/Next/Done.
- [[passport-collapse]] — Animated show and hide by height (`max-height` transition), safe for nested collapses.
- [[passport-container]] — Centered page-width wrapper that applies the design system's responsive edge padding and max width.
- [[passport-content-loader]] — Skeleton placeholders (rect, text, title, circle, thumb, circle with label) with pulse or wave shimmer.
- [[passport-corporate-interim-module]] — tiket Corporate "interim" step between product selection and checkout. Corporate users pick a travel plan and fill notes, cost centers and custom fields, including file uploads, before the booking proceeds.
- [[passport-countdown]] — `HH:MM:SS` boxed countdown timer, with optional tenths of a second, plus a `useCountdown` hook.
- [[passport-country-and-currency-modal]] — A self-triggering popup that asks the user to confirm their country and currency when the URL doesn't match their stored preferences. It also exports the country picker pieces the header reuses.
- [[passport-country-list-selection]] — Searchable country list for phone-code or nationality pickers, meant to sit inside a BottomSheet, a dropdown or a Modal.
- [[passport-currency-bottom-sheet]] — Multi-currency picker. It fetches the user's allowed currencies, lets them pick one (radio list with search), and persists the choice to cookie, account and core attributes.
- [[passport-dashboard]] — Data `Table` for back-office and B2B dashboards: sortable columns, sticky left and right columns, row-span, loading skeleton, empty state and built-in pagination.
- [[passport-date-utils]] — date-fns helpers that generate calendar grids (weeks, months, years) and compare days, shared by Calendar and Picker.
- [[passport-design-tokens]] — The foundation of Passport styling: global CSS (normalize, reset, CSS variables), the TiketOdyssey font, SCSS breakpoint and mixin helpers, and TS colour-token maps and mappers.
- [[passport-dialog]] — Centered confirmation or alert pop-up, either illustration + title + description + buttons (through [[passport-figure]]) or fully custom children.
- [[passport-divider]] — A horizontal or vertical separator line in default, bold or dashed style.
- [[passport-download-app-banner]] — "Get the tiket.com app" promo banners that link to the OneLink smart download URL.
- [[passport-dropdown]] — Headless-ish dropdown kit: `useDropdown` positions a `BaseDropdown` panel against a target, and `DropdownFormDisplay` is a read-only form field that acts as the target.
- [[passport-error-view]] — Standard error state with an illustration, localized title, description and buttons, in full-screen or inline layout.
- [[passport-extended-tabs]] — Horizontally scrollable tab bar whose tabs carry a title, subtext and content line, e.g. date tabs with prices. It has desktop arrow navigation and auto-scroll to the selected tab.
- [[passport-figure]] — Illustration + title + description + up to two buttons, for empty states, confirmations and the body of [[passport-dialog]].
- [[passport-file-upload]] — Multi-file uploader (browse or drag-and-drop, file list with retry, remove and download) and a single-file form field with a progress bar. Uploading is delegated to your `uploadFn`.
- [[passport-floating-button]] — Fixed floating action button (FAB). It can be a single icon/illustration button or an "extended" pill of several labelled buttons, with optional show-after-scroll and hide-while-scrolling behaviour.
- [[passport-focus-trap]] — Thin wrapper over `react-focus-lock` that keeps keyboard focus inside overlays and returns it to the trigger on close.
- [[passport-footer]] — tiket.com site footer: link columns, call center and contact, partner and award logos, social media and app download. It's fully responsive and driven by a `footerList` data object, with default EN/ID data included.
- [[passport-form]] — Text form fields with a floating label: `TextInput`, `TextArea`, `PhoneNumberInput`, and the shared `InputWrapper` frame that other packages build on.
- [[passport-generic-facilities]] — "Passengers & facilities" section for order-detail pages (flight, hotel, train, car, bus, ferry, airport transfer). It's server-driven through the order composer's section API, with drill-down detail popups.
- [[passport-gift-voucher-claim-widget]] — Cross-sell section ("claim these vouchers") for booking forms. It shows a carousel of claimable vouchers with T&C and a Claim button, and tracks impressions and claims.
- [[passport-gift-voucher]] — Composable "ticket stub" voucher card (header / content / perforated divider / footer) with helpers for title, link, voucher code, CTA button and expiry countdown.
- [[passport-global-popup]] — Site-wide campaign popup engine. It fetches the popups the promotion service picked for the current screen and renders them by content type (gift voucher, promo code, full image, inventory, combination, floating), with ack, interact and claim calls plus GTM.
- [[passport-global-search]] — The header's cross-vertical search box. On focus it opens a panel of server-driven "non-typing" modules (recent, popular, most-searched, inspirational, promos, info). While the user types it shows debounced keyword results (POI, verticals, SRP links).
- [[passport-google-one-tap]] — Google One Tap sign-in for logged-out web users. It loads Google Identity Services, prompts, and hands the credential to tiket's `/login` page. On desktop FedCM browsers it can show an optional AB-driven nudge banner next to the prompt.
- [[passport-gradient-banner]] — Slim, token-coloured promo or info strip (icon, text, optional timer, chevron or button). `GradientBannerContainer` turns several of them into an auto-rotating keen-slider carousel.
- [[passport-group-field-v2]] — Redesigned group-field card (Figma "Aufar - New Groupfield"). It has an optional clickable top nudge slot, rows that keep the main click surface separate from trailing selection controls, a tertiary action strip, and accessible helper/error text.
- [[passport-group-field]] — v1 "group field" card: a bordered box of tappable rows (number, text, subtext, chevron), used for booking-form sections like contact or passenger details. It also has helper/error text, an info footer and a list-with-toggle row. For new work, see [[passport-group-field-v2]].
- [[passport-header]] — The tiket.com site header: desktop top bar plus verticals row, mobile app-style bar, and slim, booking-page and auto-hiding variants.
- [[passport-highlight-discover]] — Building blocks for the "Highlight Discover" page-module sections: a layout, a mobile carousel with a cross-fading hero image, a two-up desktop article carousel, and article/product cards.
- [[passport-icons]] — About 460 inline-SVG React icon components (`IconArrowLeft`, `IconPlus`, …), generated from the SVG files in `assets/`.
- [[passport-image-preview]] — Full-screen gallery viewer for images and videos, with a slider, thumbnails, captions and keyboard navigation. It has desktop, mobile and adaptive views.
- [[passport-image-upload]] — A horizontal row of image slots. It validates the files a user picks and uploads each one, in one or more resized variants, to the tiket image service.
- [[passport-image]] — One component, `DefaultImageWrapper`: a `div` whose background is the tiket placeholder image, so the placeholder shows until (or instead of) the real image.
- [[passport-info-banner]] — An inline message box with an icon, an optional title, content, an action link and a close button. It comes in `general`, `warning` and `alert` variants and collapses when dismissed.
- [[passport-insurance-pop-up]] — Renders the flight-insurance upsell pop-up from the "Get Product Popup Display" API payload. The template is picked by `templateName`, and the same component serves verticals, webviews and the CMS panel preview.
- [[passport-insurance]] — Insurance product cards (`InsuranceProtectionCard`) and a self-contained cross-sell carousel widget (`InsuranceProtection`) that adds a protection to the standalone insurance cart and redirects to checkout.
- [[passport-kuber-price-dynamic-banner]] — Turns a Kuber "banner evaluate" API response into a rendered Passport banner (info, notification, action, gradient, voucher or price history), plus the placement info and GTM tracking that go with it.
- [[passport-label]] — Small tag or pill (`Label`) in general and product (ribbon) styles, plus `LabelCampaign`, a pill that rotates through several gradient labels.

### TIX-REACT-COMMON
- [[react-common-overview]] — pnpm-workspace monorepo of shared, mostly non-UI React/browser utilities (fetch, analytics, A/B test, env, storage, JSI bridge, remote-component loader, CI gatekeeper), published as `@tiket/react-common-*` to GitHub Packages.
- [[react-common-architecture]] — Flat `packages/*` workspace; each package builds and publishes independently, linked to its siblings with `workspace:*`.
- [[react-common-workflows]] — Feature branch → PR to `master` with a changeset → alpha snapshot on every PR push → "chore: release packages" PR → publish on merge.
- [[react-common-ab-test]] — A/B test variants from Mixpanel feature flags, client-side via a React hook and server-side via `getAbTestOnServer`.
- [[react-common-analytic]] — Client-side analytics bootstrap: gathers core attributes, writes them to `window.gtm`, initialises Amplitude and Mixpanel, sends page-visit/session events, and exposes core-attribute headers for backend tracking.
- [[react-common-core-attributes]] — Builds and persists the "core attributes" (device id, tiket session id, language, currency, country, platform, user, UTM) that every tracker and backend header uses.
- [[react-common-eagle-eye]] — Logs per-request fetch metrics (URI, sizes, status, duration, business code) to the native app's "Eagle Eye" logger when running inside the tiket app webview.
- [[react-common-env]] — `getEnvironment()`: tells which tiket environment the browser is on from `location.origin`.
- [[react-common-error-handler]] — UI half of the Central Error Handling (CEH) system: renders the bottom sheet or snackbar that the backend's error payload asks for, for errors raised through [[react-common-fetch-client]].
- [[react-common-fetch-client]] — Client-side `fetch` wrapper for tiket APIs: builds the gateway URL, adds mandatory headers, renews tokens, retries, logs to Eagle Eye and the app logger, and turns errors into Central Error Handling (CEH) responses.
- [[react-common-fetch]] — Legacy isomorphic `fetch` with session-token handling for the old Express-based "Tix React App". It is superseded by [[react-common-fetch-client]].
- [[react-common-gatekeeper]] — `tix-gatekeeper` Node CLI that runs a repo's Test, Build and Sonar Quality Gate stages in Jenkins and reports each as a GitHub check run on the commit.
- [[react-common-jsi]] — Typed wrapper around the tiket app's "generic JSI" bridge, used by web pages inside the native webview to call native commands.
- [[react-common-navigator-permission]] — One API for device features (contacts, share, calendar, location, maps) that uses browser `navigator` APIs on mweb/dweb and Cross App Routing (C.A.R) or JSI inside the tiket app webview.
- [[react-common-openapi]] — Generated `typescript-fetch` API clients for a few backend services (promocode, discount-engine, gift-voucher), built from whitelisted Swagger specs with openapi-generator-cli.
- [[react-common-push-notif]] — Registers the browser for Firebase Cloud Messaging web push, saves the token to `tix-push-notif`, and shows foreground notifications for Sendbird chat messages.
- [[react-common-queue]] — Named "task done" signals: `add(key, promise)` registers a task, `waitFor(key)` resolves once it has finished.
- [[react-common-remote]] — Host-side loader for the shared [[react-remote-overview|TIX-REACT-REMOTE]] components (header, footer, scripts, reviews, global popup…), consumed in Next.js apps through webpack [[module-federation]], with optional SSR prerender.
- [[react-common-script]] — npx CLI that bumps a consumer repo's `@tiket/react-common-*` dependencies to the latest release of their current major. It is npm-only and has no users in this workspace.
- [[react-common-storage]] — `get`/`set` for a key-value store shared across all `*.tiket.com` subdomains. It uses a hidden iframe's `localStorage`, with a cookie fallback on Safari/iOS.
- [[react-common-utilities]] — Shared helpers for every tiket web app: multi-currency formatting, the new URL structure (locale/country/currency), forwarded query params, device id and cookie helpers, client channel/OS headers, and bot detection. This is the most widely used react-common package.

- [[react-remote-workflows]] — TIX-REACT-REMOTE workflows

## Concepts
- [[ab-testing]] — Experiments and rollout flags run on **Mixpanel feature flags** (older comments say Amplitude). [[react-common-ab-test]] provides a client hook and a server fetch. Passport widgets read flags through it, and hosts can pre-fetch variants on the server and pass them down as `abTestOnServerResponse`.
- [[analytics-core-attributes]] — One set of identity and context fields (device id, session id, language, currency, country, platform, user, UTM and `tag_*` params) is computed once per page by [[react-common-core-attributes]]. It is shared through cross-subdomain storage, `postMessage` and `window.gtm`, so every tracker and backend sees the same values.
- [[central-error-handling]] — Backends can return an `errorData` payload that says how the FE should show an error (bottom sheet, snackbar, banner, embedded view) and which actions to offer. [[react-common-fetch-client]] normalises it, and one mounted `CommonErrorHandler` from [[react-common-error-handler]] renders the critical ones, so apps don't each write error UI for the same codes.
- [[changesets-fixed-versioning]] — Four of the six repos version with changesets, and they use it three different ways. Only Passport uses a `fixed` group, so every `@tiket/passport*` package always has the same version.
- [[cross-app-routing]] — To use a native capability (contact picker, calendar, maps, share) from a webview, a page navigates to a special "car request" URL. The app intercepts it, runs the native flow, and returns the result in a query parameter plus a `window.handleResponse` call. [[react-common-navigator-permission]] implements it, with browser APIs as the fallback outside the app.
- [[cross-subdomain-storage]] — tiket apps live on many hosts (`www`, `payment-*`, `m.`…), and each host has its own `localStorage`. [[react-common-storage]] gives them one shared key-value store through a hidden iframe on `storage[.<env>].tiket.com`, with a cookie fallback where browsers partition iframe storage.
- [[design-tokens]] — All Passport styling resolves to CSS custom properties defined once in [[passport-design-tokens]]. Every app must load those variables globally and compile the SCSS partials itself, because Passport ships uncompiled SCSS modules.
- [[eagle-eye-logging]] — When a tiket web page runs inside the native app, each API call's URL, method, status, timing and correlation id is reported to the app's logger (`logWebApi`), so app-side monitoring covers web screens. Outside a webview it does nothing.
- [[gatekeeper-ci]] — The PR merge gate for the app repos is Jenkins running `tix-gatekeeper` from [[react-common-gatekeeper]]. It runs test, build and SonarQube stages and reports each one as a GitHub check through a GitHub App. TIX-PASSPORT and TIX-GTM-EXTRAS don't use it.
- [[gtm-datalayer-tracking]] — Web tracking runs through one Google Tag Manager container, `GTM-PLRJPPQ`. Apps push events to `window.dataLayer` and describe the page in a global `window.gtm` object. GTM tags, [[react-common-analytic]] and the [[gtm-extras-overview|GTM extras]] pixel scripts all read that object, and no repo documents its schema.
- [[module-federation]] — TIX-REACT-REMOTE builds the header, footer and other shared widgets once as a webpack Module Federation container. The Next apps load that container at runtime through [[react-common-remote]] instead of bundling those Passport widgets themselves.
- [[multi-currency]] — Prices are formatted everywhere with one function, `createCurrencyFormatter` from [[react-common-utilities]], so the decimal places, rounding and short "calendar" amounts match across apps and Passport widgets.
- [[new-url-structure]] — tiket is moving from implicit locale (Indonesian, IDR, Indonesia) to explicit `/{lang}-{country}/...` URLs such as `/en-id/gift-card` or `/id-sg/payment`. Every layer carries an `isNewURLStructure` flag, and many defaults flip on it.
- [[passport-accessibility-font-scaling]] — Inside the tiket iOS and Android apps, Passport text follows the user's system font size. The app sets `--font-scale` on `<html>`, and [[passport-utils]] copies it into `--dynamic-type-scale`, which the `-rem` typography variables multiply by. A rollout flag gates the feature.
- [[passport-custom-fetch]] — Passport widgets that call tiket APIs don't own auth, headers or gateway routing. The host app passes its own `fetch` as `customFetch` on `PassportProvider`, and each widget switches between relative URLs (with `customFetch`) and `<endpoint>/ms-gateway/...` URLs (without it).
- [[prerelease-flow]] — "Prerelease" means two different things in this workspace. Libraries publish **npm snapshot versions** from a PR. Apps push a **prerelease git tag** that Jenkins deploys to staging. Most apps also keep a long-lived `prerelease` branch.
- [[react-remote-ssr-prerender]] — A host page can ask the TIX-REACT-REMOTE server to render remote widgets to HTML before sending the page, then hydrate them on the client through [[module-federation]]. The contract is one batch HTTP endpoint plus a set of whitelisted props.
- [[structured-diagnostic-logging]] — Both Next apps attach a "Structured Diagnostic Context" to every service call's log, so Kibana can search requests by account, email, correlation id or order id. The helper is `standardizedLogData`, and it is passed to the `@tiket/next` fetch client as `sendStandardizedLogData`.
- [[tiket-environments]] — The same five environment names (`production`, `preprod`, `staging`, `development`, `local`) appear in react-common and Passport. On the client they are derived from the hostname. Next apps get them from env vars set at build time.
- [[tiket-next-core]] — `@tiket/next` is tiket's shared Next.js toolkit (middleware, gateway fetch, logger, i18n, auth routes, build config). Both Next apps depend on it (`^3.0.0`), but its source is **not** in this workspace, so its behaviour can only be read from `node_modules` or inferred from call sites.
- [[web-push-notifications]] — Browser push (Firebase Cloud Messaging) is set up by [[react-common-push-notif]]. Apps don't call it directly: the `scripts` remote from TIX-REACT-REMOTE initialises it on every page that mounts that remote ([[react-remote-scripts]]).
- [[webview-jsi-bridge]] — Web pages that run inside the tiket Android and iOS apps talk to native code through JavaScript-interface (JSI) objects that the app injects. There are two styles, a generic request/response channel and older per-command handlers, and each repo has its own copy of the call code.

## Entities
- [[keen-slider]] — keen-slider is the third-party carousel library behind Passport's sliders. Nine packages depend on it (`^6.6.14`), and [[passport-design-tokens]] ships its stylesheet inside `base.css`.
- [[kuber]] — Kuber (`tix-kuber`) is a rules backend that decides which banner or price layout to show where, by rule, layer, priority, funnel and placement. Passport has two clients for it. Its source is not in this workspace.
- [[tix-image-service]] — The image upload and transformation backend (repo `tiket/TIX-IMAGES-BE`, not in this workspace). [[passport-image-upload]] posts images to it and asks for resized variants.
- [[tix-insurance-core]] — The insurance backend behind the standalone insurance flow, the claim center and the flight-insurance pop-up. FE code reaches it at `/ms-gateway/tix-insurance-core/...` (relative `/tix-insurance-core/...` through a host fetch). Its source is not in this workspace.
- [[tix-wishlist-core]] — The wishlist backend (a Go service, `tix-wishlist-core-go`) that stores a user's saved products ("wishes") and their collections. Only [[passport-wishlist]] calls it, and the other repos reach it through that package. Its source is not in this workspace.

## Decisions
- [[page-module-next-poc]] — **Never merge or squash `feat/page-module-next-poc` into `main` or `prerelease`** until the user says the POC has graduated.

## How-to
- [[add-new-passport-package]] — Run `npm run create:component <kebab-name>`. It scaffolds `packages/<kebab-name>` as `@tiket/passport-<kebab-name>` and also wires the package into the umbrella `@tiket/passport`. Don't create package folders by hand.
- [[local-https-certs]] — Local dev runs on `https://local.tiket.com:<port>` so that `*.tiket.com` session cookies are sent and MSW's service worker works. Each repo expects an mkcert pair, `local.tiket.com.pem` and `local.tiket.com-key.pem`, in its root. The files are gitignored and never committed.
- [[passport-local-tooling]] — The global pnpm and bun on this machine silently break installs and tests. Use the versions pinned for the repo.
- [[prerelease-squash-merge]] — Put a feature branch on the long-lived `prerelease` branch as **one** commit, done locally with git rather than the GitHub merge button. Then refresh the "Included PRs" list in the open `prerelease` → `main` PR. The user's Claude skill `squash-merge-prerelease` automates this.
- [[release-passport-package]] — Merge a PR with a changeset to `main`, then merge the "Version Packages" PR that changesets opens. Every `@tiket/passport*` package is published at the same new version. Then bump the consumers.
- [[run-tests-per-repo]] — Each repo uses a different runner and enforces coverage in a different place. Use the command in the first column and expect the gate in the last one.
